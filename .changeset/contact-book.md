Breaking: the CLI is regrouped and keeps your bots in an inbox, `~/.config/jaypost/inbox.json` (mode 0600). `init`, `uninstall` and `start` are now `jaypost service install`, `service uninstall` and `service run`, with `service start` and `service stop` added. `bot`, `key` and `pairing` moved under `jaypost admin`, as `admin bot`, `admin bot contact` and `admin bot key`, `admin-key rotate` is `admin rotate-key`, and `admin log` reads every bot's log. Admin commands take `-s NAME` to manage a remote added with `jaypost admin remote add NAME URL ADMIN_KEY`. `jaypost inbox` lists, renames, removes and sets the default of the bots in your inbox, and client commands take `-b ALIAS` (or `JAYPOST_BOT`) instead of `--port`. `jaypost admin bot key add <bot> --invite` prints a `jaypost inbox join jpi_...` line you can send to a person, and `jaypost inbox join` adds that bot and waits for pairing. `service install --exposed` listens on all interfaces over plain http and prints the `admin remote add` line for your own machine. The client `token` file is gone, and the service's files moved to `~/.config/jaypost/service/`. There is no migration: rerun `jaypost service install` on an existing install. A container install from before this release isn't detected by `service install`; stop or remove the old container first, or the new install fails with "Port 8787 is in use". See docs/hosting.md.
