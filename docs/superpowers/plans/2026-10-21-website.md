# jaypost website Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A dark, minimal, one-page Astro landing site for jaypost at `https://bithyte.github.io/jaypost/`, deployed to GitHub Pages after each release.

**Architecture:** Astro static site in `site/` with its own `package.json`. Code examples live in one TS module that both the page and a README sync check import. Two small Node checks run inside `web:build` (snippets before, built HTML after). A reusable `site.yml` workflow builds and deploys; `publish.yml` calls it after `release-assets`.

**Tech Stack:** Astro 7.x (latest is 7.4.1), plain CSS, small inline client scripts, Node 24, vite-plus tests (`vite-plus/test`) for the pure checks, GitHub Actions + Pages.

**Spec:** `docs/superpowers/specs/2026-10-21-website-design.md`

## Global Constraints

- Hosting: GitHub Pages, `site: 'https://bithyte.github.io'`, `base: '/jaypost'`. $0, no domain.
- Node 24. Site deps only in `site/package.json`; root `dependencies`/`devDependencies` unchanged; root `files` stays `["dist", "CHANGELOG.md"]`.
- Root scripts: `web:dev`, `web:build`, `web:preview`, all forwarding with `npm --prefix site run <script>`.
- Build output `site/dist`, gitignored (root `dist/` pattern already covers it; add `site/.astro/`).
- `npm run check` and `npm test` at the root keep passing.
- Every command, flag and code example on the page comes from `README.md` verbatim (whitespace may differ).
- No hardcoded version number. No analytics, trackers or third-party embeds.
- No em-dash (U+2014) anywhere in the page copy.
- `.ts` files follow the repo style (no semicolons, single quotes, width 100, strict, `.ts` import extensions) and the owner's class-per-module rules; `.astro` files follow Astro idioms.
- Don't rename `publish.yml` or change its `on:` trigger.

## Review Focus

1. Base path: any root-relative URL without `/jaypost/` (favicon, OG image, CSS, a nav link) 404s on Pages even though it works in some dev setups. Pinned by the dist check in Task 2 and the preview check in Task 5.
2. Phone width (375px): the long `curl ... | gunzip ...` one-liners and the curl request block must scroll inside their code box, never the page. Pinned in Task 5.
3. `prefers-reduced-motion: reduce`: the hero shows the finished round-trip (approved state), no motion. Pinned in Task 4.
4. JavaScript disabled: the first tab of each tab group is visible and every command is readable/selectable; only copy buttons and animation are lost. Pinned in Task 4.
5. Manual `site` run from a tag: the `github-pages` environment only allows the default branch by default, so a tag run is rejected until the owner adds a `v*` tag rule. Documented in Task 6.
